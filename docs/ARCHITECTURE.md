# 架构设计（初稿）

## 原则

- 单体优先，降低部署和维护成本。
- API 与 UI 分离，前端仅通过 `/api/v1` 访问后端。
- 持续演进：先完成正确的账单模型，再接入通知、AI 与 MCP。
- 多用户隔离、数据迁移、安全审计在正式公开部署前完成。

## 模块划分（规划）

- `catalog`：订阅、资源、类别、标签
- `billing`：计费计划、续费周期、预估账单与实际支付
- `notifications`：提醒规则、发送记录、渠道适配器
- `dashboard`：费用统计、未来支出、临期事项
- `identity`：用户、登录、授权
- `integrations`：后续 AI、MCP、导入导出

当前仅创建基础健康检查接口。上述模块尚未实现。

## 计费模型注意事项

1. 预计支出与实际支付应分表管理，禁止用预测账单充当真实流水。
2. 金额使用整数最小货币单位或 Decimal，避免 float 误差。
3. 月末、闰年、按年付费的日期运算应有单元测试。
4. 每条订阅应支持时区、首次生效日和停用日。
5. 通知记录需要幂等键，支持重试且避免重复发送。

## 部署与安全

- SQLite 是 V1 的默认候选存储；生产库的备份与迁移设计尚未完成。
- 外网部署必须配置身份验证、HTTPS、最小权限、密钥隔离、频率限制及安全响应头。
- 当前 Compose 配置只作为本机开发环境，端口绑定到 127.0.0.1。
